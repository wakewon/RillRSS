### 2.4 真实客户端：Newsboat 2.45

使用 Newsboat 的 FreshRSS（Google Reader）后端与 TT-RSS 后端分别连接：

1. 两种后端均同步到全部 33 篇文章，未读数一致。
2. 添加一个本地可控的订阅，Newsboat 同步到该新闻；随后修改该新闻（新增三段、改标题）并刷新。
3. 再次同步：两种后端都显示旧版 **已读**、新版 `[更新] …` **未读**，未读总数不变（−1 +1），与设计一致。

可用 `scripts/verify_newsboat.sh <地址> <用户名> <密码>` 对任意实例重复这一验证（需要安装 newsboat）。

### 2.5 Docker

- `docker compose up -d --build`（arm64 原生构建）：健康检查通过；服务以 uid/gid 1000 运行。
- amd64 镜像通过交叉编译构建（Apple Silicon 上 QEMU 中的 x86_64 rustc 会崩溃，故 Dockerfile 在构建平台上原生编译并交叉链接），在模拟环境中运行通过健康检查与登录。
- 处理过程中 `docker compose restart`：重启前已发布 15 篇，重启后继续处理至全部完成；随后 `--force-recreate` 重建容器；`check-db` 为 `ok`，在线备份成功；最终 32 篇文章对应 32 个故事，无重复，无错误事件。
- 发现并记录：在 Docker Desktop 中宿主机工具与容器同时访问 WAL 数据库会损坏数据库（共享内存不跨虚拟机）。已禁用 mmap、增加容器内的 `backup` / `check-db` 命令，并在 README 中警示。

### 2.7 翻译

翻译引擎与流水线通过模拟 OpenAI 兼容接口完成了全部故障场景测试（见 1）。

部署反馈的 `glm-4-flash` 故障（"请求 782 次，失败 782 次"，`HTTP 400 temperature参数非法：限制小数点[2]位`）已定位并修复：

- 原因一：温度以 `f32` 序列化，`0.2` 变成 `0.20000000298023224`，智谱接口只接受两位小数。现在按两位小数发送，模拟接口按智谱的规则校验。
- 原因二：400 错误被当作"批次过大"不断拆分重试，且不计入熔断，导致请求风暴；概览页仍显示"正常"。现在参数 / 模型 / 鉴权 / 余额类错误第一次出现即暂停翻译并提示原因，状态按最近一次请求的结果显示；排队等待并发名额的请求在发送前会再次检查暂停状态。**本环境没有可用的真实 API 密钥，也未安装本地模型，因此尚未对真实大模型进行端到端验证。** 配置真实接口后，可在后台「设置 → 测试翻译服务」或「工具 → 测试翻译」立即验证，翻译统计（请求、失败、缓存命中、Token）显示在概览页。

### 2.8 管理后台

在浏览器中逐页检查了新界面（概览、订阅、订阅详情、分类、文章、文章详情、任务、日志、设置、工具、OPML、账户、登录），包括浅色、深色和 375 px 手机宽度。使用 2.1 的 BBC 数据和模拟翻译接口实际执行了"开启翻译 → 重新处理全部文章"：40 篇文章以新 ID 发布，未读数保持 40，再次重新处理时段落全部命中缓存、不再请求接口；模拟接口返回 HTTP 400 时，概览页显示"已暂停"、错误原文与需要检查的配置。

### 2.9 独立代码审查（0.1.2）

按五个方向并行做了独立审查（处理流程与抓取、阅读器接口、AI 翻译、内容处理与网络安全、管理后台与部署），每条问题都通过阅读全部相关代码或实际运行确认，共 68 条（部分重叠），除下文"已知限制"中列出的取舍外全部修复，并为每类问题补了回归测试。重点：

- **稳定性**：深层嵌套的 HTML 曾让进程栈溢出并在每次重启后再次崩溃；现在提取、清理、切分都有深度上限，实测 2 万层嵌套的页面与 8 千层的条目都正常处理。
- **资源耗尽**：未登录请求可带 32 MB 请求体，单次让内存涨到约 2 GB；限制请求体、先认证后读取后，8 个并发的 32 MB 请求内存只增加约 1 MB。并发的错误登录不再无限占用 Argon2 内存。
- **登录限速**：伪造 `X-Forwarded-For` 曾可无限尝试密码、也可把别人锁在门外；现在只信任代理追加的地址，测试中 20 个并发猜测只有 10 个被校验。
- **重新处理**：曾可能用订阅摘要覆盖全文、吞掉待发布的新闻更新、把已被清理的文章作为未读文章重新发布；均已修复。
- **翻译**：配置导致的"输入过长"、空输出与无法解析的输出曾引发每篇几十到几百次的拆分请求；DeepSeek/OpenRouter 审核、Gemini/Groq 限流、智谱额度等错误归类修正；熔断恢复改为单个试探请求。
- **数据库**：增量回收此前从未真正启用（数据库文件不会缩小）；现在新库直接启用，旧库在 0.1.2 首次启动时用 `VACUUM` 转换一次（实测旧格式数据库从 auto_vacuum=0 变为 2，WAL 模式保持）。
- **管理后台**：OPML 导入的 `javascript:` 链接曾可执行脚本；现在只渲染 http(s) 链接，且脚本只在带本次响应 nonce 时执行。
- **部署**：安装/升级脚本在 linux/amd64 容器中按服务器目录结构完整演练过：从 0.1.0 迁移、`update.sh` 升级（自动备份数据库）、坏包升级失败后的提示与回滚。

## 3. 已知限制

- 真实大模型翻译未在本环境验证（见 2.7）；不同提供商的输出习惯可能需要调整批大小、温度、附加提示词或附加参数（如关闭思考模式）。
- 未在真实手机阅读器上实测；兼容性依据对开源客户端源码的分析、模拟同步测试与 Newsboat 实测。闭源客户端（Reeder、FeedMe、FocusReader、Fiery Feeds 等）的个别行为无法完全确认。
- 内置全文提取不执行 JavaScript、不带登录 Cookie；需要渲染或付费墙的网站请配置外部提取服务或使用订阅自带内容。
- 并发处理的文章按完成顺序发布，ID 顺序与文章发布时间不完全一致（客户端通常按时间排序，不影响增量同步）。
- TT-RSS 的评分、文章标签（tags）、`shareToPublished`、"已归档"订阅未实现；分类只有一层。搜索仅按标题与摘要做子串匹配。
- 不对图片转码（WebP/AVIF 原样提供，较老的 iOS/Android 版本可能无法显示 AVIF）。
- 未限制每日翻译 Token 预算，仅有并发与速率限制。
- 服务需部署在（子）域名根路径下，不支持路径前缀部署。
- 订阅只有一条、且新文章复用旧文章链接时，48 小时内的新文章会被当作旧文章的更新（按链接识别同一新闻的取舍）。
- 新文本不到旧文本一半时不视为实质更新（防止付费墙/错误页被当作更新），因此真正大幅删减的新闻修订不会以新版本发布。
- 使用 HTTP 代理时，目标地址先在本机解析检查，代理之后再自行解析；两次解析之间域名指向改变的情况无法完全排除。只能通过代理解析域名的网络中，原文与图片抓取需要设置 `RILL_ALLOW_PRIVATE_NETWORKS=true`。
